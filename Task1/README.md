## Проблемные места
| Проблема                               | Как проявляется                                                          | Какие сценарии страдают                       |
| -------------------------------------- | ------------------------------------------------------------------------ | --------------------------------------------- |
| 1. DWH — монолит с бизнес-логикой      | Логика размазана, код сложный, любое изменение долго                     | Быстрая отчётность, подключение новых доменов |
| 2. SQL 2008 — узкое место              | Нет масштабируемости, слабая производительность, нет колонночных движков | Аналитика, генерация отчётов, ИИ-модели       |
| 3. Трансформации выполняются в DWH     | Большая очередь ETL, долгие ночные окна                                  | Time-to-market, операционный анализ           |
| 4. Шина Camel — хрупкая                | Сложно добавлять новые сервисы, нет нормального API-соглашения           | Интеграции с новыми бизнесами                 |
| 5. Медицинские и финтех-данные смешаны | Сложно соблюдать регуляции, ACL и аудит                                  | Банковское направление, безопасность          |
| 6. PowerBuilder UI тормозит            | Нельзя масштабировать интерфейс, тяжёлое наследие                        | Клиники, операционная работа                  |
| 7. BI напрямую сидит на DWH            | Roaming запросов тормозит DWH                                            | Отчёты руководству                            |
| 8. Нет доменной модели данных          | Все данные свалены в одну систему                                        | Независимое развитие доменов                  |
| 9. Нет портала самообслуживания        | Все отчёты собирают аналитики вручную                                    | Скорость принятия решений                     |

## Приоритизация (MoSCoW)

### Must (критично)

1. Разделить данные по доменам (ввести Data Products).
2. Убрать бизнес-логику из DWH в домены.
3. Развернуть Lakehouse как новую платформу данных.
4. Внедрить портал самообслуживания.
5. Обеспечить безопасное хранение финтех-данных отдельно.
6. API-gateway + мастер-данные перенести из Camel.

### Should (желательно как можно раньше)

1. Добавить Event Bus для потоковых данных.
2. Начать миграцию BI от DWH к витринам.
3. Автоматизировать lineage, качество данных, SLA.

### Could (хорошо бы, но не критично)

1. Обновить интерфейс PowerBuilder на современный web.
2. Добавить единый каталог данных для всех доменов.

### Won’t (пока не делаем)

1. Полный отказ от Camel сразу — только адаптация.
2. Миграция всех подсистем HO — можно оставить частично.
3. Полный отказ от MS SQL 2008
