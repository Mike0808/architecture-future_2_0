# 1. ДОМЕНЫ

Домены данных это самостоятельные единицы экосистемы, которые должны развиваться независимо и поставлять свои Data Products.

## Домен 1.  Клиники

**Что внутри:**

* медкарты (но остаются в операционном контуре, в аналитику не попадают),
* записи визитов, назначения, процедуры,
* обезличенные клинические события,
* медицинская статистика,
* операционная отчётность для клиник.

**Для чего нужен домен:**

* клиники хотят развиваться независимо от финтеха;
* ИИ-сервисы питаются обезличенными потоками из этого домена;
* медданные — зона контроля регуляторов и рисков, их нельзя «мешать» с остальными.

**Бизнес-сценарии:**

* загрузка клиник, эффективность врачей;
* показания к ИИ-аналитике;
* развитие новых медицинских услуг;
* подключение нового партнёра-производителя медоборудования (данные от устройств).


## Домен 2. Финтех

**Что внутри:**

* транзакции, счета, кредитные продукты;
* рисковые модели;
* клиентская финстатистика;
* отчётность для банка и надзора.

**Для чего нужен домен:**

* финтех должен развиваться без зависимости от медицинских данных;
* очень жёсткие требования по доступу (банковская лицензия);
* новые финтех-продукты (кредитование пациентов, страхование, BNPL) должны создаваться быстро.

**Бизнес-сценарии:**

* кредит под медуслуги;
* риск-скоринг с учётом непрямых мед.показателей (обезличенных);
* отчётность для Центробанка.

## Домен 3. ИИ / Аналитика

**Что внутри:**

* модели ИИ, которые обучаются на обезличенных данных;
* фичи и feature store;
* inference API.

**Для чего нужен домен:**

* ИИ должен использовать данные из медицины, но без возможности ‘re-identify’;
* этот домен может развиваться сам: новые модели, новые сервисы;
* сюда же подключатся будущие партнёры из фармацевтики (клинические исследования).

**Бизнес-сценарии:**

* детекция аномалий по визитам, диагнозам, расходам;
* мед-ИИ: анализ снимков, прогноз осложнений;
* фармпартнёры: модели для R&D.

---

## Домен 4. Головной офис (управленческий)

**Что внутри:**

* фин.отчётность;
* персонал;
* инвентарь;
* мотивация;
* сводная аналитика по всем доменам.

**Для чего нужен домен:**

* управленцам нужны отчёты в едином формате;
* все домены поставляют сюда агрегированные данные, а не «сырые» таблицы;
* это основной потребитель доменных DDP.

**Бизнес-сценарии:**

* быстрые отчёты по всей компании;
* анализ прибыли/убытка по направлениям;
* принятие решений на уровне холдинга.

# Логика разделения и выгоды

### 1. Медицинский домен

**Почему обособлен:** медданные — самые чувствительные, требуют обезличивания, жёстких ACL, отдельного compliance.
**Выгода:**

* ИИ может обучаться на данных без риска раскрытия.
* Клиники развиваются независимо.

### 2. Финтех домен

**Почему обособлен:** банковская лицензия, отдельный надзор, другие SLA, другие API.
**Выгода:**

* можно запускать новые кредиты, BNPL, страхование, не трогая мед.системы;
* упрощается отчётность для регуляторов.

### 3. ИИ-домен

**Почему обособлен:** модели обучаются и развиваются независимо от транзакционных систем.
**Выгода:**

* можно быстро добавлять новые модели;
* легко подключать внешние фарм-партнеров и производителей оборудования.

### 4. Домены данных (DDP) для каждого направления

**Почему обособлен:** каждый домен должен владеть своими витринами, а не складывать всё в один DWH.
**Выгода:**

* независимые циклы обновления;
* нет необходимости переписывать старый DWH;
* меньше конфликтов между командами.

### 5. Головной офис (управленческий слой)

**Почему обособлен:** это потребитель доменных витрин, а не источник.
**Выгода:**

* отчёты формируются быстро из DDP, а не из монолитного DWH;
* можно строить отчёты по компании целиком без боли.
